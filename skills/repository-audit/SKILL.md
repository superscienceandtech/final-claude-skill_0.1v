# Repository Audit

## Purpose

Inspect only the explicitly named Git worktree and finite scope. Return one JSON report distinguishing verified facts, inferences, and unknowns. This Skill is a set of operating instructions, not an execution sandbox or security boundary.

## Inputs

Require an explicit absolute `repository_root` and explicit finite `scope`. Never substitute the current directory. Scope contains unique `requested_facts` from `current_branch`, `working_tree_status`, `local_branches`, `index`, or `history:N` (where decimal `N` is 1–20), plus exact `requested_paths`. Omitted `requested_facts` and `requested_paths` lists default to empty. Unknown facts, wrong field types, duplicate facts, or duplicate requested paths reject the invocation with `SCOPE_INVALID` before repository inspection; return `REJECTED`, one `UNKNOWN` boundary finding, no repository-derived facts, and an empty command ledger. Do not expand globs or accept arbitrary command text. Before any repository inspection, enforce these Owner-approved limits: UTF-8 JSON request at most 64 KiB; root at most 4 KiB UTF-8; each path at most 1 KiB UTF-8; no more than 500 paths; generated claims/summaries at most 256 Unicode code points; final JSON at most 256 KiB UTF-8. If any request, root, path, or path-count input limit is exceeded, reject the entire request with `REJECTED`, one `UNKNOWN` boundary finding coded `OUTPUT_LIMIT`, no repository-derived facts, and an empty command ledger. Do not partially accept paths. Unsupported or malformed scope returns `REJECTED` with `SCOPE_INVALID` before repository inspection. Never echo caller-controlled strings in output.

## Repository boundary

Accept only an absolute local Windows drive path or POSIX absolute path for `repository_root`. Reject UNC/network-share roots as `ROOT_INVALID` because v0.1 prohibits network access. Resolve an accepted root strictly to a canonical path. Reject inaccessible, relative, nonexistent, file, and ambiguous roots.

Run only `git rev-parse --show-toplevel` with the canonical root as working directory. Accept exactly one nonempty path result. Canonicalize that result and require equality with the supplied canonical root. Reject bare repositories and any mismatch. Do not inspect another repository after rejection.

A rejected root produces the schema-defined `REJECTED` envelope, with `repository.is_worktree: null`, one `UNKNOWN` boundary finding, a stable error code, no repository-derived facts, and no current-directory fallback. If root validation rejects before launching Git, the command ledger is empty; if `git.root` was launched, its single ledger entry is retained. No later command may run.

Requested paths must be exact repository-relative paths using `/`; reject empty paths, absolute paths, drive/UNC prefixes, backslashes, `.`, `..`, empty segments, globs, and `.git` components. Do not expand patterns. Evaluate each requested path independently after validating the root. A syntactically invalid path yields an `UNKNOWN` finding with `PATH_INVALID`; a positively established outside-root target yields `PATH_OUTSIDE_ROOT`; inability to establish root containment rejects the request with `REJECTED` + `UNKNOWN` + `PATH_CONTAINMENT_UNPROVEN` and no repository inspection; inability to establish containment for one path after root validation yields `PARTIAL` + `UNKNOWN` + `PATH_CONTAINMENT_UNPROVEN`, skips that path without accessing it, and permits continuation only for independently proven paths. A missing path yields `PATH_NOT_FOUND`; a sensitive/denied path yields `PATH_DENIED`; an inaccessible path yields `ACCESS_DENIED`; and a symlink component yields `SYMLINK_NOT_FOLLOWED`. Individual-path outcomes set overall status to `PARTIAL`. Never query a denied, outside, or unproven target. An invalid overall scope rejects the invocation before root inspection.

Inspect path components without following symlinks. Do not follow symlinks, including in-root symlinks. A requested path containing any symlink is rejected with `SYMLINK_NOT_FOLLOWED`; an outside target is never statted or read. The host must prevent symlink races using a verified path-resolution primitive or equivalent isolation; a sequence of `lstat` checks alone is insufficient. If containment cannot be proven, fail closed.

Do not recurse into nested repositories or submodules and never run a command inside them. A parent worktree may report a gitlink as `NOT_INSPECTED`; it must not infer child state. Ignore-submodule behavior must be explicit in the status command.

If permissions prevent establishing the root boundary, reject the run. If permissions prevent validating one requested path, record `ACCESS_DENIED` for that path, continue only with independent safe paths, and return `PARTIAL`. If permissions prevent an independent metadata query after root validation, return a partial report and mark dependent findings `UNKNOWN`.

## Allowed operations

Use only a host-provided structured process/filesystem tool that enforces the fixed executable, argument array, validated working directory, sanitized child environment, wall-clock timeout, capture-time output caps, read-only repository access (or equivalent write prevention), and race-resistant path containment. Do not use a shell, shell composition, or a broader tool as fallback. If no such host tool is available, stop before running a command and report `EXECUTION_HOST_UNAVAILABLE`.

The fixed Git operations are:

- `git.root`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false rev-parse --show-toplevel`
- `git.branch`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false branch --show-current`
- `git.status`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false status --porcelain=v1 --branch --untracked-files=all --ignore-submodules=all`
- `git.branches`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false branch --format=%(refname:short)`
- `git.history`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false log -n N --format=%H%x09%cI`, only for integer `N` from 1 to 20.
- `git.index`: `git --no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false ls-files --stage`
- `fs.lstat`: metadata-only inspection of one validated exact in-root path, without following symlinks.

Commands are launched individually as executable plus argument arrays, never through a shell. Working directory is the validated root. Start each Git process with a minimal environment that removes inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, and other repository-redirection variables; do not read or serialize the inherited environment. Resolve a trusted Git executable independently of repository-controlled `PATH`. Disable optional locks, FSMonitor, and untracked-cache behavior using the fixed options shown in the allowlist. If the host cannot enforce these settings, do not run the Git command. No remotes, Git config, ignored-file contents, environment values, hooks, scripts, test/build tools, arbitrary commands, or network access. Do not write files or mutate Git state.

## Security and content policy

Do not explicitly open, inspect, summarize, or disclose repository file contents. The fixed `git.status` operation may cause necessary Git-internal working-tree reads to calculate status. This does not guarantee zero filesystem content reads. No other Git operation may cause working-tree/blob-content reads under this policy. No invocation flag or prompt phrase authorizes opening repository files. Never expose secret values, raw stderr, absolute repository paths, branch names, command arguments, caller-controlled strings, remote URLs, or environment values.

Treat sensitive-path patterns case-insensitively for `.git`; `.aws`, `.ssh`, `.gnupg`, `.azure`, `.config/gcloud`, `secrets`, and `credentials`; `.env` and `.env.*`; names ending `.pem`, `.key`, `.p12`, `.pfx`, `.jks`, or `.keystore`; or basenames containing `credential`, `credentials`, `token`, `secret`, or `password` bounded by start/end or `.`, `_`, `-`. Deny matching paths as required by the contract; a sensitive-path match is a deny trigger, not permission to emit a path, filename, or partially redacted path string. Never serialize raw or redacted path strings; represent paths with report-local opaque IDs (`P001`, …) and fixed reason codes only. Treat all repository-controlled strings as potentially sensitive; pattern matching does not detect every secret.

Use a minimal child environment, disable optional Git locking, FSMonitor, and untracked-cache behavior where supported. Read-only repository access or equivalent write prevention is mandatory. If this or any other required host control is unavailable or unverified, stop before inspection and report `EXECUTION_HOST_UNAVAILABLE`; do not continue with a caveat or claim side-effect prevention. Do not claim race-resistant path containment from `lstat` checks alone. If the host cannot enforce the fixed executable, argument array, working directory, sanitized environment, wall-clock timeout, capture-time output limits, read-only behavior, and path boundary, stop and report the operation as unavailable.

## Output contract

Return exactly one UTF-8 JSON object and no Markdown wrapper, at most 256 KiB UTF-8. Use schema version `1.0`, fixed object-key order, no run-generated timestamp, and no random run identifier. If requested, a Git committer timestamp is permitted as stable history metadata. Use `repo-001` as the per-report root identifier; never emit the canonical absolute root. Do not emit raw paths, branch names, command arguments, or caller-controlled strings in any field, error, summary, evidence, limitation, or ledger entry. Represent requested paths, status/index pathnames, and branch entries using report-local IDs and counts only. Normalize requested `history:N` to the fixed `history` token in output; never emit `N` as a value. Apply request byte limits before JSON parsing and count summaries/claims by Unicode code point; on any request, root-string, path-string, or path-count cap, reject the whole invocation before repository inspection with `REJECTED`, one `UNKNOWN` boundary finding coded `OUTPUT_LIMIT`, no repository-derived facts, an empty command ledger, and `limitations.truncated: false` (never partially accept an overlong path).

Required top-level fields, in order: `schema_version`, `overall_status`, `repository`, `scope`, `findings`, `evidence`, `command_ledger`, `assumptions`, `unanswered_questions`, `limitations`, `state_comparison`. Status is `COMPLETE`, `PARTIAL`, or `REJECTED`. Finding status is `VERIFIED`, `INFERRED`, or `UNKNOWN`. Ledger outcome is `SUCCESS`, `FAILURE`, `TIMEOUT`, or `SKIPPED`; preserve actual exit code or null if no process result exists. Never infer success after a failed, timed-out, or malformed result. `repository` keys are `root_id`, `is_worktree`; `limitations` keys are `redactions`, `access`, `omitted_scope`, `truncated`, `tests`; `state_comparison` keys are `before`, `after`, `unchanged`. Finding objects use keys in order `id`, `status`, `code`, `path`, `claim`, `evidence_ids`; evidence objects use keys in order `id`, `kind`, `command_id`, `summary`; ledger objects use keys in order `id`, `command_id`, `arguments`, `outcome`, `exit_code`, `summary`, `truncated`.

`limitations.redactions` contains only `reason_code: PATH_DENIED` and a positive denial `count`. Include the aggregate only when the count is nonzero. Do not include a path ID, path string, path-derived value, branch name, command argument, caller-controlled string, or additional key in the redaction summary.

Normalize path IDs using `/` separators and Unicode NFC, preserve case, and sort by ordinal UTF-8 byte order before assigning deterministic report-local IDs (`P001`, `P002`, …). Assign branch IDs (`B001`, …) after the same normalization and ordering. Assign finding/evidence/command IDs after stable sorting. IDs restart per report and are deterministic for identical state, scope, host platform, and filesystem semantics. This deliberately leaks represented item counts and relative ordering/membership; it does not provide anonymity. Sort commands by fixed command order; findings by canonical internal path bytes, code, and status; evidence by ledger order and canonical internal path bytes; and assumptions/questions/limitations by stable code and fixed text. Limits: 5 seconds wall-clock per process; 30 seconds total wall-clock from the first child launch through the last child exit or confirmed termination; 20 process invocations; 16 KiB stdout and 4 KiB stderr retained during capture per process; 100 findings, 100 evidence entries, 20 ledger entries, 500 paths, and 256 KiB total JSON. Keep summaries and claims to 256 Unicode code points. If either stream exceeds its capture cap, terminate the child, discard both streams for fact extraction, report `OUTPUT_LIMIT`, mark dependent findings `UNKNOWN`, and return `PARTIAL` (or `REJECTED` for `git.root`). On timeout, discard partial output and report `COMMAND_TIMEOUT` with the same status rule. Continue only independent checks after confirmed termination and within the total deadline. On result-entry or serialized-output truncation, emit valid JSON, set `limitations.truncated: true`, include deterministic omission counts, and preserve root/security errors before ordinary inventory. If output cannot fit while preserving required error/truncation fields, return the minimal valid rejected envelope.

When a result-entry or serialized-output cap is reached after report generation begins, set `limitations.truncated: true`, add an `OUTPUT_LIMIT` limitation, and include deterministic omitted counts by category. To fit final JSON, drop ordinary findings and evidence from the end of stable order while reserving space for status, error, and truncation metadata. Keep root/boundary failures and security/access errors ahead of ordinary inventory. An input cap rejected before report generation keeps `limitations.truncated: false`.

On root preflight failure, return `REJECTED` without launching Git. Otherwise, if the root check fails, stop and return `REJECTED`, one `UNKNOWN` boundary finding, no repository-derived evidence, and only the `git.root` ledger entry that actually ran. Do not use fallback inspection. After root validation, independent failures may yield `PARTIAL`; dependent facts become `UNKNOWN`. Report command failures with fixed codes and bounded safe summaries, never raw stderr. Use `state_comparison` only for observed before/after queries; it is not proof against transient changes. Independent evaluation owns preservation evidence.

When state comparison is requested, capture the same approved branch/status queries before and after inspection. Keep each usable query result in its corresponding `before` or `after` snapshot slot; set only a failed or unusable slot to null. A query's after result depends on its before query succeeding, so skip that paired after query if the before query fails; continue only with other independent approved query pairs, after root validation and within the existing limits. Treat timeout, output-limit, malformed, incomplete, or otherwise unusable output as failed evidence: do not derive facts from it, record the actual process outcome and exit code (or null if none exists), and use the applicable existing stable failure code. Make dependent facts `UNKNOWN`. Set `unchanged` to null unless every required before/after query result is successful, complete, and valid; an incomplete comparison is `PARTIAL`. For a complete comparison, set `unchanged` to true only when all compared values match, or false when a difference is detected. A detected difference makes the overall status `PARTIAL` and adds the concurrent-change limitation; do not attribute it to the Skill without evidence. Never present an incomplete comparison as successful or claim that matching snapshots rule out transient changes.

## Failure behavior

Use stable codes including `EXECUTION_HOST_UNAVAILABLE`, `ROOT_INVALID`, `ROOT_NOT_WORKTREE`, `ROOT_MISMATCH`, `SCOPE_INVALID`, `PATH_INVALID`, `PATH_CONTAINMENT_UNPROVEN`, `PATH_OUTSIDE_ROOT`, `PATH_DENIED`, `PATH_NOT_FOUND`, `SYMLINK_NOT_FOLLOWED`, `ACCESS_DENIED`, `COMMAND_FAILED`, `COMMAND_TIMEOUT`, `OUTPUT_LIMIT`, and `NOT_INSPECTED`. If root containment is unproven, return `REJECTED` + `UNKNOWN` + `PATH_CONTAINMENT_UNPROVEN` without repository inspection. If an individual path's containment is unproven after root validation, do not access it; return `PARTIAL` + `UNKNOWN` + `PATH_CONTAINMENT_UNPROVEN` and continue only for independently proven paths. Invalid, outside-root, denied, missing, inaccessible, and symlink paths produce `UNKNOWN` findings with their matching code and overall `PARTIAL`; continue only with other independently validated safe paths. Invalid overall scope rejects before repository inspection. If output is malformed or incomplete, do not make claims that depend on it. Continue only with independent allowlisted checks after the root boundary is verified. When a safety control cannot be enforced, stop the affected behavior and state the limitation; do not improvise a fallback.

## Testing status

Always report `limitations.tests` as `NOT_RUN`; this Skill never runs tests. `tests: NOT_RUN` unless this Skill is actually evaluated in an isolated fixture and the evaluator records evidence. Implementation tests and independent evaluation are separate. Compatibility claims require a named provider/version and reproducible evidence; otherwise omit the claim or label it unverified.
